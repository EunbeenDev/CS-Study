# 5.2 B-Tree 자료구조

## 5.2.1 B-Tree의 개념과 구조
- B-Tree (Balanced Tree) 는 다진 탐색 트리(M-ary Search Tree) 기반의 균형 트리
- 주로 데이터베이스 인덱스, 파일 시스템에서 사용

### 특징
- 하나의 노드가 여러 개의 키와 자식 포인터를 가짐
- 모든 리프 노드는 같은 depth (높이) 에 존재 → 항상 균형 유지
- 노드 내 키는 정렬된 상태 유지
- 각 노드는 키와 자식 포인터로 구성

### 구조
- 한 노드의 최대 자식 수: m
- 한 노드의 키 개수: m-1 이하
- 루트를 제외한 모든 노드는 최소 ⌈m/2⌉개의 자식을 가짐
- 키 개수 = 자식 수 - 1
```scss
[ 10 | 20 | 30 ]
/     |     \
...   ...   ...

```
- 각 키는 구간 분할 역할
- 왼쪽 subtree < 키 < 오른쪽 subtree


## 5.2.2 왜 효율적인가?
### 시간복잡도: O(log n)
- B-Tree는 항상 균형 상태 유지
- 높이 h ≈ logₘ(n)
- 탐색, 삽입, 삭제 모두 트리 높이에 비례
- 탐색: O(log n)
- 삽입: O(log n)
- 삭제: O(log n)

### 디스크 I/O 최적화
B-Tree가 DB에서 쓰이는 진짜 이유는 디스크 접근 최소화 때문이다.
#### 이유
- 한 노드가 여러 키를 한 번에 저장 (block 단위) → 한 번 디스크 읽으면 많은 데이터 비교 가능

그 결과, 트리 높이가 매우 낮아짐 → 디스크 접근 횟수 감소 (I/O cost ↓)

### 균형 유지 메커니즘
- 삽입 시 노드가 가득 차면 → Split (분할), 중간 키를 부모로 올림
- 삭제 시 키가 부족하면 → Merge (병합) 또는 Redistribute (재분배)
- 항상 균형 유지 → 최악의 경우에도 O(log n) 보장
