# 4.1 데이터베이스 개념

- 데이터베이스(Database)
  - 데이터의 집합체로, 특정 목적을 위해 조직화된 데이터의 모음
  - 일정한 규칙과 구조에 따라 저장되어 효율적으로 관리될 수 있도록 설계됨
  - 다양한 형태로 존재 (관계형, NoSQL 등)
  - 응용 프로그램과 데이터베이스 사이에 인터페이스 역할을 하는 데이터베이스 관리 시스템(DBMS)을 통해 접근


## 4.1.1 Entity

### Entity 개념
  - 현실 세계의 객체나 개념을 나타내는 추상적인 개체
  - 데이터베이스에서 엔터티는 테이블로 표현되며, 각 행은 엔터티의 인스턴스를 나타냄
  - 예시: 학생, 강의, 도서 등

### 약한 엔터티(Weak Entity)와 강한 엔터티(Strong Entity)
  - 강한 엔터티: 고유한 식별자를 가지고 독립적으로 존재할 수 있는 엔터티
  - 약한 엔터티: 고유한 식별자가 없으며, 다른 엔터티에 의존하여 존재하는 엔터티
  - 예시: 학생(강한 엔터티)과 수강신청(약한 엔터티) - 수강신청은 학생에 의존하여 존재


## 4.1.2 Relation

### Relation 개념
  - 엔터티 간의 연관성을 나타내는 개념
  - 데이터베이스에서는 관계(Relation)로 표현되며, 테이블 간의 연결을 의미
  - 예시: 학생과 강의 간의 수강 관계


## 4.1.3 Attribute(속성)
### Attribute 개념
  - 엔터티의 특성을 나타내는 데이터 요소
  - 데이터베이스에서는 테이블의 열로 표현되며, 각 열은 특정 속성을 나타냄
  - 예시: 학생 엔터티의 이름, 학번, 전공 등

## 4.1.4 Domain(도메인)
### Domain 개념
- 속성이 가질 수 있는 값의 범위를 정의하는 개념
- 데이터베이스에서는 각 속성에 대해 허용되는 값의 집합을 지정하여 데이터의 무결성을 유지
- 예시: 학생의 학번은 숫자로만 구성되어야 한다는 도메인 제약 조건

## 4.1.5 Field와 Record
### Field(필드) 개념
- 데이터베이스에서 하나의 속성을 나타내는 단위
- 테이블의 열에 해당하며, 특정 속성의 값을 저장하는 공간
- 예시: 학생 테이블에서 이름, 학번, 전공 등이 필드에 해당

### Record(레코드) 개념
- 데이터베이스에서 하나의 엔터티 인스턴스를 나타내는 단위
- 테이블의 행에 해당하며, 각 행은 특정 엔터티의 속성
- 예시: 학생 테이블에서 한 학생의 이름, 학번, 전공이 하나의 레코드로 표현됨


## 4.1.5 Relationship(관계)
### Relationship 개념
- 엔터티 간의 연관성을 나타내는 개념
- 데이터베이스에서는 테이블 간의 연결을 의미하며, 외래 키(Foreign Key)를 통해 표현됨
- 예시: 학생과 강의 간의 수강 관계

## 4.1.6 Key(키)
### Key 개념
- 데이터베이스에서 레코드를 고유하게 식별하는 속성 또는 속성
- 주요 키(Primary Key): 테이블에서 각 레코드를 고유하게 식별하는 속성
- 외래 키(Foreign Key): 다른 테이블의 주요 키를 참조하여 테이블 간의 관계를 표현하는 속성
- 예시: 학생 테이블에서 학번이 주요 키로 사용되고, 수강신청 테이블에서 학생의 학번이 외래 키로 사용될 수 있음

### Key 종류

- 주요 키(Primary Key): 테이블에서 각 레코드를 고유하게 식별하는 속성
- 후보 키(Candidate Key): 주요 키로 선택될 수 있는 속성 또는 속성
- 대체 키(Alternate Key): 후보 키 중에서 주요 키로 선택되지 않은 속성
- 외래 키(Foreign Key): 다른 테이블의 주요 키를 참조하여 테이블 간의 관계를 표현하는 속성
- 복합 키(Composite Key): 여러 속성을 조합하여 레코드를 고유하게 식별하는 키
- 슈퍼 키(Super Key): 레코드를 고유하게 식별할 수 있는 속성 또는 속성의 집합
- 인조 키(Surrogate Key): 시스템에서 자동으로 생성되는 고유한 식별자, 실제 데이터와는 무관한 키
