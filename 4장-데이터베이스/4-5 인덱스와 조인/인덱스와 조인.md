# 4.5 인덱스와 조인
## 4.5.1 인덱스의 필요성
- 데이터를 빠르게 찾을 수 있는 하나의 장치
- 인덱스가 없는 경우, 데이터베이스는 전체 테이블을 검색하여 원하는 데이터를 찾아야 하므로 시간이 오래 걸린다.
- 인덱스는 데이터베이스에서 검색 속도를 향상시키는 데 중요한 역할을 한다.
- 인덱스는 데이터베이스의 성능을 향상시키고, 대량의 데이터를 효율적으로 관리할 수 있도록 도와준다.


## 4.5.2 B-트리
- B-트리는 데이터베이스에서 인덱스를 구현하는 데 널리
- 사용되는 자료구조로, 균형 잡힌 트리 구조를 가지고 있다.
- 노드가 여러 개의 자식을 가질 수 있으며, 각 노드는 키와 포인터를 포함한다.
- 데이터베이스에서 검색, 삽입, 삭제 연산을 효율적으로 수행할 수 있도록 설계되어 있다.

### B-트리의 데이터 검색 과정
1. 루트 노드에서 시작하여 검색하려는 키와 비교한다.
2. 검색하려는 키가 현재 노드의 키보다 작으면 왼쪽 자식으로 이동하고, 크면 오른쪽 자식으로 이동한다.
3. 자식 노드에서도 같은 과정을 반복하여 검색하려는 키를 찾는다.
4. 검색하려는 키가 노드에 존재하면 해당 데이터를 반환하고, 존재하지 않으면 검색이 실패한다.


### 인덱스가 효율적인 이유와 대수확장성
- B-트리는 균형 잡힌 트리 구조를 가지고 있어 검색, 삽입, 삭제 연산이 O(log n)의 시간 복잡도를 가진다.
- 대량의 데이터가 있는 경우에도 효율적으로 검색할 수 있다.
- 인덱스는 데이터베이스의 성능을 향상시키고, 대량의 데이터를 효율적으로 관리할 수 있도록 도와준다.

#### 대수확장성이란?
- 대수확장성은 데이터베이스 시스템이 데이터의 양이 증가하더라도 성능이 크게 저하되지 않는 능력을 의미한다.
- B-트리와 같은 인덱스 구조는 대수확장성을 제공하여, 데이터베이스가 대량의 데이터를 효율적으로 관리할 수 있도록 도와준다.

## 4.5.3 인덱스 최적화 기법
- 인덱스는 데이터베이스의 성능을 향상시키지만, 잘못된 인덱스 설계는 오히려 성능을 저하시킬 수 있다.
- 인덱스 최적화 기법에는 다음과 같은 방법들이 있다
    - 1. 적절한 인덱스 선택
        자주 검색되는 열에 인덱스를 생성하여 검색 속도를 향상시킨다.
    - 2. 복합 인덱스 사용
        여러 열을 조합하여 인덱스를 생성하여 검색 성능을 향상시킨다.
    - 3. 인덱스 유지 관리
        인덱스가 최신 상태로 유지되도록 정기적으로 업데이트하고, 불필요한 인덱스를 제거하여 성능을 최적화한다.



# 4.6 조인의 종류
## 4.6.1 내부 조인 (Inner Join)
- 내부 조인은 두 테이블에서 일치하는 레코드만 반환하는 조인 방식이다.
- 예시
  - 학생 테이블과 수강신청 테이블을 내부 조인하여 학생이 수강 신청한 강의 정보를 가져오는 경우
  - 학생 테이블과 수강신청 테이블에서 일치하는 학생의 레코드만 반환된다.

## 4.6.2 왼쪽 조인 (Left Join)
- 왼쪽 조인은 왼쪽 테이블의 모든 레코드와 오른쪽 테이블에서 일치하는 레코드를 반환하는 조인 방식이다.
- 예시
  - 학생 테이블의 모든 레코드와 수강신청 테이블에서 일치하는 학생의 레코드가 반환된다. 
  - 만약 수강신청 테이블에 일치하는 레코드가 없는 학생이 있다면, 해당 학생의 레코드는 반환되지만 수강신청 정보는 NULL로 표시된다.
## 4.6.3 오른쪽 조인 (Right Join)
- 오른쪽 조인은 오른쪽 테이블의 모든 레코드와 왼쪽 테이블에서 일치하는 레코드를 반환하는 조인 방식이다.
- 예시
  - 수강신청 테이블의 모든 레코드와 학생 테이블에서 일치하는 학생의 레코드가 반환된다. 
  - 만약 학생 테이블에 일치하는 레코드가 없는 수강신청이 있다면, 해당 수강신청의 레코드는 반환되지만 학생 정보는 NULL로 표시된다.

## 4.6.4 합집합 조인 (Full Outer Join)
- 합집합 조인은 두 테이블의 모든 레코드를 반환하는 조인 방식이다. 일치하는 레코드는 하나로 합쳐지고, 일치하지 않는 레코드는 NULL로 표시된다.
- 예시
  - 학생 테이블과 수강신청 테이블의 모든 레코드가 반환된다. 
  - 일치하는 레코드는 하나로 합쳐지고, 일치하지 않는 레코드는 NULL로 표시된다.

# 4.7 조인의 원리
## 4.7.1 중첩 루프 조인 (Nested Loop Join)
- 중첩 루프 조인은 두 테이블의 모든 레코드를 비교하여 일치하는 레코드를 찾는 조인 방식이다.
- 예시
  - 학생 테이블과 수강신청 테이블을 중첩 루프 조인하여 학생이 수강 신청한 강의 정보를 가져오는 경우
  - 학생 테이블의 각 레코드에 대해 수강신청 테이블의 모든 레코드를 비교하여 일치하는 레코드를 찾는다.

## 4.7.2 정렬 병합 조인 (Sort-Merge Join)
- 정렬 병합 조인은 두 테이블을 정렬한 후, 정렬된 결과를 병합하여 일치하는 레코드를 찾는 조인 방식이다.
- 예시
  - 학생 테이블과 수강신청 테이블을 각각 정렬한 후, 정렬된 결과를 병합하여 일치하는 레코드를 찾는다.

## 4.7.3 해시 조인 (Hash Join)
- 해시 조인은 한 테이블의 레코드를 해시 테이블에 저장한 후, 다른 테이블의 레코드를 해시 테이블과 비교하여 일치하는 레코드를 찾는 조인 방식이다.
- 예시
  - 학생 테이블의 레코드를 해시 테이블에 저장한 후, 수강신청 테이블의 레코드를 해시 테이블과 비교하여 일치하는 레코드를 찾는다.
