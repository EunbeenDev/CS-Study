# 4.2 ERD와 정규화 과정

## 4.2.1 ERD의 중요성
- ERD(Entity-Relationship Diagram)는 데이터베이스 설계에서 중요한 도구
- 현실 세계의 객체와 그들 간의 관계를 시각적으로 표현하는 다이어그램
- ERD를 통해 데이터베이스 구조를 명확히 이해하고, 효율적인 데이터 모델링이 가능

## 4.2.2 정규화 과정

- 정규화(Normalization)는 데이터베이스 설계에서 데이터의 중복을 최소화하고, 데이터 무결성을 유지하기 위한 과정
- 정규화 과정은 여러 단계로 나뉘며, 각 단계는 특정한 규칙을 만족해야 함

### 1. 제1정규형(1NF)
- 모든 속성이 원자값(Atomic Value)을 가져야 함
- 즉, 각 필드는 더 이상 나눌 수 없는 단일 값을 가져야 함
- 예시: 학생 테이블에서 전화번호 필드가 여러 개의 번호를 포함하는 경우, 이를 분리하여 각각의 번호를 별도의 레코드로 표현

### 2. 제2정규형(2NF)
- 제1정규형을 만족하면서, 모든 비주요 속성이 기본 키에 완전 함수적 종속(Full Functional Dependency)을 가져야 함
- 즉, 기본 키의 일부에만 종속된 속성이 없어야 함
- 예시: 학생 테이블에서 학생 ID와 강의 ID가 기본 키인 경우, 학생 이름이 학생 ID에만 종속되어 있다면, 학생 이름을 별도의 테이블로 분리하여 학생 ID에만 종속되도록 해야 함

### 3. 제3정규형(3NF)
- 제2정규형을 만족하면서, 모든 비주요 속성이 기본 키에 직접적으로 종속(Directly Dependent)되어야 함
- 즉, 비주요 속성이 다른 비주요 속성에 종속되어서는 안 됨
- 예시: 학생 테이블에서 학생 ID가 기본 키인 경우, 학생 이름이 학생 ID에 종속되어 있고, 학생 이름이 학생 주소에 종속되어 있다면, 학생 주소를 별도의 테이블로 분리하여 학생 이름에 종속되지 않도록 해야 함

### 4. 보이스-코드 정규형(BCNF)
- 제3정규형을 만족하면서, 모든 결정자가 후보 키(Candidate Key)이어야 함
- 즉, 모든 결정자가 기본 키 또는 후보 키여야 함
- 예시: 학생 테이블에서 학생 ID와 강의 ID가 후보 키인 경우, 학생 ID가 강의 ID를 결정하는 경우, 학생 ID를 별도의 테이블로 분리하여 학생 ID가 후보 키가 되도록 해야 함
