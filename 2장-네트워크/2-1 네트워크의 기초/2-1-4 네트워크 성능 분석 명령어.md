코드 상의 문제가 없는데도 사용자가 서비스로부터 데이터를 가져오지 못한다면, 네트워크 병목 현상의 가능성이 크다.
네트워크 병목 현상의 주된 원인은 다음과 같아.
- 네트워크 대역폭
- 네트워크 토폴로지
- 서버 CPU, 메모리 사용량
- 비효율적인 네트워크 구성

네트워크로 인한 문제라고 확인된 경우, 다음과 같은 명령어들을 통해 네트워크 성능 분석을 해야 한다.
1. ping
2. netstat
3. nslookup
4. tracert(traceroute)

ping(Packet INternet Groper)
- 네트워크 상태를 확인하려는 대상 노드를 향해 일정  크기의 패킷을 전송하는 명령어
- 알 수 있는 정보
  - 해당 노드의 패킷 수신 상태
  - 도달하기까지의 시간
  - 해당 노드까지 네트워크가 잘 연결되어 있는지의 여부
- ICMP 프로토콜을 통해 동작하므로, 
  - ICMP 프로토콜을 지원하지 않거나
  - 네트워크 정책상 ICMP나 tracetoute를 차단하는 경우
  - ping 테스트가 불가하다.
```shell
ping www.google.com -n 12 
# [-n 12] 12번의 패킷을 보내고 12번의 패깃을 받아라
```

netstat
- 접속되어 있는 서비스들의 네트워크 상태를 표시
- 알 수 있는 정보
  - 프로토콜, 로컬 주소, 외부 주소, 상태 등
  - 현재 접속하고 있는 사이트들에 관한 네트워크 상태 리스트
- 주로 서비스의 포트가 열려있는지 확인할 때 사용

nslookup
- DNS에 관련된 내용을 확인하기 위해 사용
- 특정 도메인에 매핑된 IP를 확인하기 위해 사용

tracert(traceroute)
- 윈도우는 `tracert`, 리눅스는 `tracetroute`
- 목적지 노드까지 네트워크 경로를 확인할 때 사용
- 알 수 있는 정보
  - 각 경로에 따른 응답시간
- 목적지 노드까지 구간들 중 어느 구간에서 응답 시간이 느려지는지를 확인 가능
