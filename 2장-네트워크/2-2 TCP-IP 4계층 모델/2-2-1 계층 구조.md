OSI 7계층 vs TCP/IP 4계층

| OSI 표준 모델 | 주요 프로토콜 / 주소 / 매체               | TCP/IP 모델 |
|--------------|---------------------------------|-------------|
| 응용 계층     | DHCP, FTP, DNS, HTTP, POP, SMTP | 응용 계층 |
| 표현 계층     | DHCP, FTP, DNS, HTTP, POP, SMTP | 응용 계층 |
| 세션 계층     | DHCP, FTP, DNS, HTTP, POP, SMTP | 응용 계층 |
| 전송 계층     | TCP, UDP                        | 전송 계층 |
| 네트워크 계층 | IP 주소 (IPv4, IPv6)              | 인터넷 계층 |
| 데이터 링크 계층 | MAC 주소                          | 네트워크 접근 계층 |
| 물리 계층     | 이더넷 케이블, 와이어                    | 네트워크 접근 계층 |

> ### 용어
> - FTP
>   - 장치와 장치 간의 파일을 전송하는 데 사용되는 표준 통신 프로토콜
> - SSH
>   - 보안되지 않은 네트워크에서 네트워크 서비스를 안전하게 운영하기 위한 암호화 네트워크 프로토콜
> - HTTP
>   - World Wide Web을 위한 데이터 통신의 기초이자 웹 사이트를 이용하는 데 쓰는 프로토콜
> - SMTP
>   - 전자 메일 전송을 위한 인터넷 표준 통신 프로토콜
> - DNS
>   - 도메인 이름과 IP 주소를 매핑해주는 시스템/프로토콜


애플리케이션(Application) 계층
- 응용 프로그램이 사용되는 프로토콜 계층
- 웹 서비스, 이메일 등 서비스를 실질적으로 제공하는 층

전송(Transport) 계층
- 애플리케이션과 인터넷 계층 사이의 데이터가 전달될 때 중계 역할
- 대표적으로 TCP, UDP가 있다.
- 송신자와 수신자를 연결하는 통신 서비스를 제공
- 연결 지향 데이터 스트림 지원
- 신뢰성 제공
- 흐름 제어

> ### TCP와 UDP
> 1. TCP (예: 카카오톡)
>    - 패킷 사이의 순서 보장
>    - 연결지향 프로토콜 사용
>    - 신뢰성 구축
>    - 수신 여부 확인
>    - 가상회선 패킷 교환 방식 사용
> 2. UDP (예: 유튜브)
>    - 순서 보장 X
>    - 수신 여부 확인 X
>    - 데이터그램 패킷 교환 방식 사용

패킷 교환 방식
1. 가상회선 패킷 교환 방식
   - 각 패킷에 가상회선 식별자가 포함
   - 모든 패킷을 전송한 뒤에는 가상회선이 해제
   - 패킷들은 전송된 '순서대로' 도착
2. 데이터그램 패킷 교환 방식
   - 패킷이 독립적으로 이동 -> 도착 순서 보장 X
   - 각 패킷이 최적의 경로를 선택하여 이동
   - 하나의 메세지에서 분할된 여러 패킷은 서로 다른 경로로 전송될 수 있다

### TCP가 신뢰성을 확보하는 방법

TCP는 연결 성립과 해제 과정을 통해 **신뢰성 있는 데이터 전송**을 보장한다.


### 1. 연결 성립 과정 – 3-way Handshake
- 3-way handshake를 통해 **상호 통신 가능 여부를 확인**하고  
  **초기 시퀀스 번호(Sequence Number)를 동기화**한다.

#### 1) SYN 단계
- 클라이언트가 서버에게 연결 요청을 보내며 `SYN` 플래그를 설정
- 초기 시퀀스 번호(Sequence Number)를 함께 전송
- 상태 **SYN_SENT**

#### 2) SYN + ACK 단계
- 서버가 클라이언트의 요청을 수락하고 `SYN`과 `ACK` 플래그를 함께 전송
- 서버의 초기 시퀀스 번호와 클라이언트 시퀀스 번호에 대한 응답 포함
- 상태
    - 서버 → **SYN_RECEIVED**

#### 3) ACK 단계
- 클라이언트가 서버의 응답을 확인하고 `ACK` 플래그를 전송
- 이로써 양쪽 모두 연결이 정상적으로 설정됨
- 상태
    - 클라이언트 / 서버 → **ESTABLISHED**


### 2. 연결 해제 과정 – 4-way Handshake
- 4-way handshake는 **양방향 통신을 각각 독립적으로 종료**함으로써  
  연결을 안전하게 해제하고 **데이터 손실을 방지**한다.

#### 1) FIN 단계
- 연결을 종료하려는 측(Active Close)이 `FIN` 플래그를 전송
- 더 이상 전송할 데이터가 없음을 알림
- 상태
    - 종료 요청 측 → **FIN_WAIT_1**

#### 2) ACK 단계
- 상대방(Passive Close)이 종료 요청을 확인하고 `ACK` 플래그를 전송
- 상태
    - 종료 요청 측 → **FIN_WAIT_2**
    - 종료 요청을 받은 측 → **CLOSE_WAIT**

#### 3) FIN 단계
- 상대방도 자신의 데이터 전송이 끝났음을 알리기 위해 `FIN` 플래그를 전송
- 상태
    - FIN 전송 측 → **LAST_ACK**

#### 4) ACK 단계
- 최초 종료 요청자가 `ACK` 플래그를 전송
- 상태
    - ACK 전송 측 → **TIME_WAIT**
    - FIN 전송 측 → **CLOSED**


> #### `TIME_WAIT` 상태
>- 소켓이 바로 소멸되지 않고 일정 시간 유지되는 상태
>- 일정 시간(보통 **2 × MSL**) 동안 대기 후 연결 완전 종료
>- 목적
>    - 지연된 패킷이 새로운 연결에 영향을 주는 것을 방지
>    - 마지막 ACK 손실 시 재전송을 보장
>- TIME_WAIT 종료 후 상태 → **CLOSED**
>- 리눅스는 60초, 윈도우는 4분으로 설정되어 있으며, 이는 OS마다 다르다.


인터넷(internet) 계층
- 장치롭부터 받은 네트워크 패킷을 IP 주소를 통해 지정된 목적지로 전송하기 위해 사용되는 계층
- IP, ARP, ICMP 프로토콜 사용
- 패킷을 수신해야 할 상대의 주소를 지정해 데이터를 전달
- 비연결형적 특성(수신 확인 과정X)


링크(link) 계층
- 전선, 광섬유, 무선 등을 사용해 실질적으로 데이터를 전달하는 계층
- 장치 간 신호를 주고받는 '규칙'을 정하는 계층
- 네트워크 접근 계층이라고도 불림
- OSI 7계층에서는 이를 데이터 링크 계층, 물리 계층으로 나눈다.
  - 데이터 링크 계층: '이더넷 프레임'을 통해 에러 확인, 흐름 제어, 접근 제어를 담당하는 계층
  - 물리계층: 무선 LAN과 유선 LAN을 통해 0,1로 이루어진 데이터를 보내는 계층

#### LAN(Local Area Network) 구성 요소 및 통신 방식 정리

### 1. 전이중화 통신 (Full-Duplex)
- 송신과 수신을 **동시에** 수행하는 통신 방식
- 충돌(Collision)이 발생하지 않음
- 예: 스위치 기반 이더넷


#### 2. 반이중화 통신 (Half-Duplex)
- 송신과 수신을 **동시에 할 수 없음**
- 한쪽이 송신 중일 때 다른 쪽은 대기
- 충돌 발생 가능
- 예: 초기 이더넷, Wi-Fi


#### 3. 트위스트 페어 케이블 (Twisted Pair Cable)
- 두 개의 구리선을 **꼬아서** 만든 케이블
- 전자기 간섭(EMI)을 줄이기 위함
- 종류: UTP, STP
- 주로 **이더넷 통신**에 사용


#### 4. 광섬유 케이블 (Fiber Optic Cable)
- 전기 신호가 아닌 **빛**을 이용한 전송 매체
- 전송 속도가 빠르고 장거리 전송 가능
- 전자기 간섭에 강함
- 데이터센터, 백본 네트워크에 사용


#### 5. Wi-Fi (Wireless Fidelity)
- 무선 LAN 기술 (IEEE 802.11)
- 전파를 이용해 통신
- 반이중화 통신 방식
- 이동성과 설치 편의성이 높음


#### 6. BSS (Basic Service Set)
- 하나의 **AP(Access Point)** 와 이에 연결된 단말들의 집합
- Wi-Fi 네트워크의 기본 단위
- 하나의 무선 셀(Cell) 형성


#### 7. ESS (Extended Service Set)
- 여러 개의 BSS를 **유선 네트워크로 연결**한 구조
- 동일한 SSID 사용
- 사용자는 이동 중에도 끊김 없이 통신 가능 (로밍)


#### 8. 이더넷 프레임 (Ethernet Frame)
- 데이터 링크 계층에서 사용하는 데이터 단위
- 구성 요소:
    - 목적지 MAC 주소
    - 출발지 MAC 주소
    - 타입(Type)
    - 데이터(Data)
    - FCS (오류 검출)


#### 9. MAC 주소 (Media Access Control Address)
- 네트워크 인터페이스에 할당된 **고유 식별자**
- 48비트(6바이트) 주소
- 데이터 링크 계층에서 사용
- 예: `00:1A:2B:3C:4D:5E`

### 1. 계층 간 송수신 과정
- 네트워크 통신은 **계층 구조**를 따라 이루어짐
- 송신 측에서는 **상위 계층 → 하위 계층**으로 데이터 전달
- 수신 측에서는 **하위 계층 → 상위 계층**으로 데이터 전달
- 각 계층은 **바로 인접한 계층과만 통신**


### 2. 캡슐화 (Encapsulation) 과정
- 송신 측에서 데이터를 전송할 때 수행
- 상위 계층의 데이터에 **하위 계층의 제어 정보(Header)** 를 추가
- 계층을 내려갈수록 헤더가 계속 추가됨

#### 계층별 흐름
- 응용 계층 데이터
  → 전송 계층: TCP/UDP 헤더 추가
  → 네트워크 계층: IP 헤더 추가
  → 데이터 링크 계층: MAC 헤더 + 트레일러(FCS) 추가
  → 물리 계층: 비트(Bit) 단위 전송


### 3. 비캡슐화 (Decapsulation) 과정
- 수신 측에서 데이터를 처리할 때 수행
- 하위 계층부터 **헤더를 하나씩 제거**
- 제거된 데이터는 상위 계층으로 전달됨

#### 계층별 흐름
- 물리 계층: 비트 수신
  → 데이터 링크 계층: MAC 헤더 제거
  → 네트워크 계층: IP 헤더 제거
  → 전송 계층: TCP/UDP 헤더 제거
  → 응용 계층: 원본 데이터 전달
