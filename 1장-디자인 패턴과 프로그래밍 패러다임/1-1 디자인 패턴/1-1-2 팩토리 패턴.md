### 1. 팩토리 패턴(Factory pattern)이란?
- 객체를 사용하는 코드에서 객체 생성 부분을 분리해 추상화한 패턴
- 객체 생성을 공장(Factory) 클래스로 캡슐화 처리하여 대신 생성하게 하는 생성 디자인 패턴
- 상속 관계에 있는 두 클래스에서 상위 클래스가 중요한 뼈대를 결정하고, <br> 하위 클래스에서 객체 생성에 관한 구체적인 내용을 결정하는 패턴

### 2. 장점
- 상위 클래스와 하위 클래스가 분리되기 때문에 결합도가 낮아진다.
- 상위 클래스에서는 인스턴스 생성 방식에 대해 알 필요가 없기 때문에 유연성을 더 가진다.
- 객체를 생성하는 로직과 사용하는 로직이 분리되어 있어 유지보수성이 증가한다.
- 생성자(Creator)와 구현 객체(concrete product)의 강한 결합을 피할 수 있다.
- 캡슐화, 추상화를 통해 생성되는 객체의 구체적인 타입을 감출 수 있다.
- SRP(단일 책임 원칙)을 따른다: 객체 생성의 책임을 분리한다.
- OCP(개방/폐쇄 원칙)을 따른다: 기존 코드를 수정하지 않고 새로운 인스턴스를 도입할 수 있다.

### 3. 팩토리 패턴의 종류
구분 기준은 "누가 어떤 객체를 생성하는지 결정하는가?"이다.
1. 단순 팩토리 패턴(Simple Factory Pattern) - 팩토리 클래스가 결정
2. 팩토리 메소드 패턴(Factory Method Pattern) - 서브 클래스가 결정
3. 추상 팩토리 패턴(Abstract Factory Pattern) - 팩토리 구현체가 결정

책에서 사용된 예시는 팩토리 메소드 패턴이므로 이를 기준으로 설명한다.

### 4. 예시
#### 0) 구조
```scss
Application (Creator)
 ├─ openDocument()        ← 템플릿 메소드
 └─ createDocument()     ← Factory Method (추상)
        ↑
        │
 ┌───────────────┐
 │               │
WordApplication  PdfApplication   (ConcreteCreator)
        │               │
        ↓               ↓
WordDocument      PdfDocument     (ConcreteProduct)
        ↑               ↑
        └────── Document ────────┘ (Product)

```
#### 1) Product — 제품 추상화
- 팩토리 메소드가 생성할 객체의 공통 인터페이스
```java
// Product
public interface Document {
    void open();
}
```
#### 2) ConcreteProduct — 실제 생성되는 객체
- Product 인터페이스를 구현한 실제 객체
```java
// ConcreteProduct
public class WordDocument implements Document {
    public void open() {
        System.out.println("Word 문서 열기");
    }
}
```
```java
public class PdfDocument implements Document {
    public void open() {
        System.out.println("PDF 문서 열기");
    }
}
```
#### 3) Creator — 최상위 공장 클래스
- Factory Method 패턴의 중심 클래스
```java
// Creator
public abstract class Application {
    // 템플릿 메소드
    public void openDocument() {
        Document doc = createDocument(); 
        doc.open();
    }

    protected abstract Document createDocument(); // 팩토리 메소드
}
```
#### 5. ConcreteCreator — 서브 공장 클래스
- Factory Method를 구현하여 실제 객체를 생성
- 객체 생성 책임을 서브 클래스에 분산
```java
// ConcreteCreator
public class WordApplication extends Application {
    protected Document createDocument() {
        return new WordDocument();
    }
}
```
```java
public class PdfApplication extends Application {
    protected Document createDocument() {
        return new PdfDocument();
    }
}
```



### 참고1) Template 패턴 vs. Factory 패턴
템플릿 패턴은 행동패턴이고, 팩토리 패턴은 생성 패턴이다.

다만 클래스 구조의 결은 거의 같다. <br>
인스턴스를 생성하는 공장을 템플릿 패턴으로 구성한 것이 팩토리 패턴이 되기 때문이다.<br>

템플릿 패턴에서는 하위 클래스에서 구체적인 처리 알고리즘의 내용을 만들도록 추상 메소드를 상속 시켰다.<br>
이 로직을 알고리즘 내용이 아닌 인스턴스 생성에 적용한 것이 팩토리 패턴이다.<br>
