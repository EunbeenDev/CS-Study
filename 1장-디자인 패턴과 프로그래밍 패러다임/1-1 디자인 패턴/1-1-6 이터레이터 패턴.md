## 1-1-6. 이터레이터 패턴 (Iterator Pattern)

### 1. 이터레이터 패턴이란?

* **집합 객체(Collection)의 내부 구조를 노출하지 않고**,
  그 요소들을 **순차적으로 접근할 수 있는 방법을 제공**하는 행동 디자인 패턴
* 반복 로직을 컬렉션이 아닌 **전용 이터레이터 객체**로 분리한다

> “컬렉션이 어떻게 저장되어 있는지는 몰라도, 순회는 가능하게 한다.”

---

### 2. 장점

* 컬렉션의 내부 구현(Array, List, Tree 등)을 숨길 수 있다
* 순회 로직을 분리하여 **SRP(단일 책임 원칙)** 을 만족한다
* 다양한 순회 방식(정방향, 역방향 등)을 쉽게 추가할 수 있다
* 동일한 인터페이스로 서로 다른 컬렉션을 순회할 수 있다

---

### 3. 구성 요소

1. **Iterator**: 요소 접근 인터페이스
2. **ConcreteIterator**: 실제 순회 구현
3. **Aggregate**: 컬렉션 인터페이스
4. **ConcreteAggregate**: 실제 컬렉션

---

### 4. 예시

```java
public interface Iterator {
    boolean hasNext();
    Object next();
}
```

```java
public class NameIterator implements Iterator {
    private String[] names;
    private int index = 0;

    public NameIterator(String[] names) {
        this.names = names;
    }

    public boolean hasNext() {
        return index < names.length;
    }

    public Object next() {
        return names[index++];
    }
}
```
