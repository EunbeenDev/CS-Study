## 프록시 패턴
### 1. 프록시 패턴(Proxy pattern)이란?
- 다른 객체에 대한 접근을 제어하기 위한 대리 객체(Proxy) 를 제공하는 구조 디자인 패턴
- 실제 객체(Real Subject)에 직접 접근하지 않고, 프록시 객체를 통해 간접적으로 접근하도록 만든다.
- 접근 제어, 지연 로딩, 로깅, 캐싱, 보안 등의 부가 기능을 실제 객체를 수정하지 않고도 추가할 수 있다.
- 실제 객체 앞에 대리인(proxy)을 하나 세워서, 접근을 통제할 수 있게 함

### 2. 장점
- 실제 객체의 생성/접근 비용을 제어할 수 있다.
- 부가 기능(보안, 로깅, 캐싱 등)을 공통 로직으로 분리할 수 있다.
- 실제 객체의 변경 없이 기능을 확장할 수 있어 OCP(개방/폐쇄 원칙)을 만족한다.
- 클라이언트는 프록시인지 실제 객체인지 몰라도 되므로 결합도가 낮다.
핵심 비즈니스 로직과 부가 로직을 분리하여 SRP(단일 책임 원칙)을 만족한다.

### 3. 프록시 패턴의 구성 요소
구분 기준은 “누가 실제 객체를 대신하는가?” 이다.
- Subject (공통 인터페이스): RealSubject와 Proxy가 구현해야 할 인터페이스
- RealSubject (실제 객체): 핵심 비즈니스 로직을 수행
- Proxy (대리 객체): RealSubject에 대한 접근을 제어

### 4. 예시
#### 0) 구조
```scss
   Client
   │
   ▼
   Proxy  ───────────▶  RealSubject
   │                   (실제 객체)
   └── 접근 제어 / 캐싱 / 로깅
```

#### 1) Subject — 공통 인터페이스
```java
// Subject
public interface Image {
   void display();
}
```

#### 2) RealSubject — 실제 객체
```java
// RealSubject
   public class RealImage implements Image {

       private String fileName;
    
       public RealImage(String fileName) {
           this.fileName = fileName;
           loadFromDisk();
       }
    
       private void loadFromDisk() {
        System.out.println(fileName + " 로딩 중...");
       }
    
       public void display() {
        System.out.println(fileName + " 표시");
   }
}
```
   

#### 3) Proxy — 대리 객체

실제 객체 생성을 지연(Lazy Loading)
```java
// Proxy
public class ImageProxy implements Image {

    private RealImage realImage;
    private String fileName;

    public ImageProxy(String fileName) {
        this.fileName = fileName;
    }

    public void display() {
        if (realImage == null) {
            realImage = new RealImage(fileName);
        }
        realImage.display();
    }
}
```


#### 4) 사용 예
```java
public class Client {
   public static void main(String[] args) {
        Image image = new ImageProxy("test.png");

        image.display(); // 실제 객체 생성
        image.display(); // 재사용
   }
}
```
   

### 5. 프록시 패턴의 종류
| 종류         | 설명             |
| ---------- | -------------- |
| **가상 프록시** | 실제 객체 생성을 지연   |
| **보호 프록시** | 접근 권한 제어       |
| **원격 프록시** | 원격 객체를 로컬처럼 사용 |
| **캐싱 프록시** | 결과 캐싱          |
| **로깅 프록시** | 호출 전후 로깅       |

## 프록시 서버 (Proxy Server)
### 1.프록시 서버란?
- 클라이언트와 서버 사이에 위치한 중계 서버
- 클라이언트의 요청을 대신 받아 서버로 전달하고, 서버의 응답을 다시 클라이언트에게 전달
- 네트워크 레벨에서 구현된 프록시 패턴의 대표적인 사례
  - 클라이언트가 서버와 직접 통신하지 않게 한다.

### 2. 프록시 서버의 역할
- 보안 강화 
- 실제 서버 IP 은닉 
- 접근 제어, 인증 
- 캐싱 
- 동일 요청에 대해 응답 재사용 
- 트래픽 제어 
- 로드 감소 
- 로깅 및 모니터링 
- 콘텐츠 필터링

### 3. 프록시 서버의 종류
#### 1) 포워드 프록시 (Forward Proxy)
```scss
Client → Proxy → Server
```
- 클라이언트 앞에 위치하여 클라이언트를 보호한다.
- 내부 네트워크 → 외부 접근 제어
- 예: 사내 인터넷 접속 제어, 학교/회사 네트워크

#### 2) 리버스 프록시 (Reverse Proxy)
```scss
Client → Proxy → Internal Server
```
- 서버 앞에 위치하여 서버를 보호한다.
- 클라이언트는 실제 서버를 모름
- 예: Nginx, AWS ALB, CloudFront


프록시 서버는 프록시 패턴을 네트워크에 적용한 것이다.


### 참고1) Spring에서의 프록시 패턴
- Spring은 프록시 패턴을 적극적으로 사용한다.
- AOP
  - 트랜잭션(@Transactional)
  - 로깅 
  - 보안

- Spring Data JPA
  - Lazy Loading (프록시 엔티티)
- @Async
- @Cacheable
```scss
Bean → Proxy Bean → 실제 Bean
```
