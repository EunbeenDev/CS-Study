
## 1-2-3. 절차지향 프로그래밍 (Procedural Programming)

### 절차지향 프로그래밍이란?

* **프로그램을 순차적인 절차(명령어)의 흐름**으로 구성하는 패러다임
* 함수는 있지만, 데이터와 로직이 명확히 분리되지 않음

---

### 특징

* 위에서 아래로 흐르는 실행 구조
* 상태 변경이 빈번
* 전역 변수 사용 가능

---

### 예시

```java
int sum = 0;
for (int i = 0; i < arr.length; i++) {
    sum += arr[i];
}
```

---

### 장단점

#### 장점

* 구조가 단순
* 성능 예측이 쉬움
* 소규모 프로그램에 적합

#### 단점

* 규모가 커질수록 유지보수 어려움
* 변경에 취약
* 코드 재사용성 낮음

---

### 객체지향 vs 절차지향

| 구분    | 객체지향  | 절차지향  |
| ----- | ----- | ----- |
| 중심    | 객체    | 함수/절차 |
| 상태 관리 | 객체 내부 | 전역/외부 |
| 확장성   | 높음    | 낮음    |
| 유지보수  | 유리    | 불리    |

---

## 정리
* 패러다임은 정답이 아니라 **도구**이다.
* 상황에 맞게 선택하거나 조합하는 능력이 중요하다.
* 실제로 **객체지향을 중심으로 함수형/선언형을 함께 사용**한다.

> 좋은 코드는 패러다임을 잘 아는 것에서 시작된다.
