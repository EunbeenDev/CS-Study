# 2. 메모리
메모리는 컴퓨터 시스템에서 데이터를 저장하고 접근하는 데 사용되는 하드웨어 구성 요소이다. <br>
CPU가 데이터를 빠르게 읽고 쓸 수 있도록 지원하며, 프로그램 실행에 필요한 데이터를 일시적으로 저장하는 역할을 한다. <br>
여러 계층으로 구성되어 있으며, 각 계층은 속도와 용량 측면에서 서로 다른 특성을 가지고 있다.

## 2.1 메모리 계층
속도가 빠른 순서(용량에 반비례)로 메모리 계층을 나열하면 다음과 같다.
1. 레지스터(Register)
   - CPU 내부에 위치한 고속 메모리
   - 명령어 실행에 필요한 데이터를 일시적으로 저장
   - 가장 빠른 메모리 계층이지만 용량이 매우 작음
2. 캐시 메모리(Cache Memory)
   - CPU와 메인 메모리 사이에 위치한 고속 메모리
   - 자주 사용되는 데이터와 명령어를 저장하여 CPU의 접근 속도를 향상시킴
   - L1, L2, L3 캐시로 구분되며, L1이 가장 빠르고 용량이 작음
3. 메인 메모리(Main Memory)
   - RAM(Random Access Memory)으로도 불리는 주 메모리
   - 프로그램과 데이터를 저장하는 주요 메모리 계층
   - 하드 디스크로부터 일정량의 데이터를 복사해서 임지 저장하고, 이를 필요 시에 CPU가 접근하여 사용
   - CPU가 직접 접근할 수 있으며, 휘발성 메모리로 전원이 꺼지면 데이터가 사라짐
4. 보조 기억 장치(Secondary Storage)
   - 하드 디스크 드라이브(HDD), 솔리드 스테이트 드라이브(SSD) 등으로 구성된 대용량 저장 장치
   - 비휘발성 메모리로, 데이터를 영구적으로 저장
   - CPU가 직접 접근할 수 없으며, 데이터는 메인 메모리를 통해 접근해야 함
   - 속도가 가장 느리지만 용량이 가장 큼
   - 운영체제는 보조 기억 장치에 저장된 데이터를 필요할 때 메인 메모리로 로드하여 CPU가 사용할 수 있도록 함

### 캐시
- 캐시는 CPU와 메인 메모리 사이에 위치한 고속 메모리
- 데이터를 미리 복사하여 저장해두는 임시 저장소
- 빠른 장치와 느린 장치 사이의 속도 차이(병목 현상)를 줄이는 역할을 한다.
- 자주 사용되는 데이터와 명령어를 저장하여 CPU의 접근 속도를 향상시키는 역할을 한다.

- L1, L2, L3로 구분되며, L1이 가장 빠르고 용량이 작으며, L3가 가장 느리지만 용량이 크다.

캐시의 주요 목적은 CPU가 메인 메모리에 접근하는 시간을 줄이는 것이다. <br>
캐시는 프로그램의 지역성 원칙을 활용하여 자주 사용되는 데이터와 명령어를 저장한다. <br>
- 시간 지역성(Temporal Locality): 최근에 사용된 데이터나 명령어가 다시 사용될 가능성이 높다는 원칙
- 공간 지텩성(Spatial Locality): 인접한 메모리 주소에 있는 데이터나 명령어가 함께 사용될 가능성이 높다는 원칙

### 캐시히트와 캐시미스(feat. 캐시 매핑)
- 캐시 매핑(Cache Mapping): 캐시 히트 또는 미스를 결정하기 위해 메인 메모리의 주소를 캐시의 주소로 변환하는 방법을 말한다. <br>
  - 직접 매핑(Direct Mapping), 연관 매핑(Associative Mapping), 집합 연관 매핑(Set-Associative Mapping) 등이 있다.
  - 직접 매핑: 메인 메모리의 각 블록이 캐시의 특정 라인에 매핑되는 방식
  - 연관 매핑: 메인 메모리의 블록이 캐시의 어느 라인에나 매핑될 수 있는 방식
  - 집합 연관 매핑: 메인 메모리의 블록이 캐시의 특정 집합에 매핑되고, 집합 내에서는 연관 매핑이 적용되는 방식
- 캐시 히트(Cache Hit): CPU가 필요한 데이터나 명령어가 캐시에 존재하여 빠르게 접근할 수 있는 경우
- 캐시 미스(Cache Miss): CPU가 필요한 데이터나 명령어가 캐시에 존재하지 않아 메인 메모리에서 데이터를 가져와야 하는 경우
캐시 미스가 발생하면 CPU는 메인 메모리에 접근하여 데이터를 가져와야 하므로, 처리 속도가 느려진다. 따라서 캐시의 효율성을 높이는 것이 중요하다.

> #### 캐시 작동 과정
> 1. CPU가 명령어를 실행하기 위해 필요한 데이터나 명령어에 접근하려고 할 때, 먼저 캐시를 확인한다.
> 2. 캐시에 필요한 데이터나 명령어가 존재하면, <br> **캐시 히트**가 발생하여 CPU는 캐시에서 데이터를 빠르게 읽어온다.
> 3. 캐시에 필요한 데이터나 명령어가 존재하지 않으면, <br> **캐시 미스**가 발생하여 CPU는 시스템 버스를 통해 메인 메모리에 접근하여 데이터를 가져와야 한다.
> 4. 메인 메모리에서 데이터를 가져온 후, CPU는 해당 데이터를 캐시에 저장하여 다음에 접근할 때 빠르게 사용할 수 있도록 한다.
> 
> 캐시의 효율성을 높이기 위해 운영체제는 캐시 관리 알고리즘을 사용하여 어떤 데이터를 캐시에 저장할지 결정한다. (예: LRU, FIFO, LFU 등)

### 웹 브라우저의 캐시
#### 쿠키
- 웹 브라우저가 웹사이트에서 사용자 정보를 저장하기 위해 사용하는 작은 데이터 파일
- 사용자 인증, 사이트 설정, 쇼핑 카트 정보 등을 저장하는 데 사용됨
- 웹사이트가 사용자의 브라우저에 쿠키를 설정하면, 이후 방문 시 해당 쿠키를 읽어 사용자에게 맞춤형 경험을 제공할 수 있음
- 쿠키는 도메인과 경로에 따라 구분되며, 보안 설정에 따라 HTTPOnly, Secure 등의 속성을 가질 수 있음
#### 로컬 스토리지
- 웹 브라우저가 웹사이트에서 데이터를 클라이언트 측에 저장하기 위해 사용하는 API
- 쿠키와 달리, 로컬 스토리지는 더 큰 용량(최대 5MB 이상)을 제공하며, 데이터는 브라우저 세션 간에도 유지됨
- 키-값 쌍으로 데이터를 저장하며, JavaScript를 통해 쉽게 접근하고 조작할 수 있음
- 도메인과 경로에 따라 구분되며, 보안 설정에 따라 접근 권한을 제어할 수 있음
#### 세션 스토리지
- 웹 브라우저가 웹사이트에서 데이터를 클라이언트 측에 저장하기 위해 사용하는 API
- 로컬 스토리지와 유사하지만, 세션 스토리지는 브라우저 세션이 종료되면 데이터가 삭제됨
- 키-값 쌍으로 데이터를 저장하며, JavaScript를 통해 쉽게 접근하고 조작할 수 있음
- 도메인과 경로에 따라 구분되며, 보안 설정에 따라 접근 권한을 제어할 수 있음

### 데이터베이스의 캐싱 계층(feat. Redis)
- 데이터베이스 시스템에서 자주 사용되는 데이터를 메모리에 저장하여 빠르게 접근할 수 있도록 하는 기술
- Redis
  - 인메모리 데이터 구조 저장소로, 데이터베이스의 캐싱 계층에서 자주 사용되는 데이터를 메모리에 저장하여 빠르게 접근할 수 있도록 하는 역할을 한다.
  - 키-값 쌍으로 데이터를 저장하며, 다양한 데이터 구조(문자열, 해시, 리스트, 셋 등)를 지원한다.
  - 높은 성능과 낮은 지연 시간으로 인해 데이터베이스 캐싱 계층에서 자주 사용되며, 데이터베이스의 부하를 줄이고 응답 속도를 향상시키는 데 도움을 준다.



## 2.2 메모리 관리
운영체제는 메모리를 효율적으로 관리하기 위해 다양한 메모리 관리 기법을 사용한다. <br>
- 가상 메모리(Virtual Memory): 실제 메모리보다 더 큰 메모리를 사용할 수 있도록 하는 기술로, 보조 기억 장치의 일부를 메모리처럼 사용하는 방식
- 페이징(Paging): 메모리를 고정 크기의 페이지로 나누어 관리하는 방식으로, 메모리 단편화를 줄이고 효율적인 메모리 사용을 가능하게 함
- 세그멘테이션(Segmentation): 메모리를 가변 크기의 세그먼트로 나누어 관리하는 방식으로, 프로그램의 논리적 구조에 맞게 메모리를 할당할 수 있도록 함
- 메모리 보호(Memory Protection): 각 프로세스가 자신에게 할당된 메모리 영역만 접근할 수 있도록 하는 기능으로, 시스템 안정성과 보안을 향상시킴

### 가상 메모리
추상화를 통해 실제로 물리적인 메모리보다 더 큰 메모리를 사용할 수 있도록 하는 기술로, <br>
보조 기억 장치의 일부를 메모리처럼 사용하는 방식이다. <br>
가상 주소 공간을 제공하여 프로그램이 실제 메모리 크기에 관계없이 필요한 만큼의 메모리를 사용할 수 있도록 한다. <br>
운영체제는 가상 주소를 물리 주소로 변환하는 메모리 관리 유닛(MMU)을 사용하여 가상 메모리를 구현한다. <br>

> #### TLB (Translation Lookaside Buffer)
> - 가상 주소를 물리 주소로 변환하는 과정에서 자주 사용되는 주소 매핑 정보를 저장하는 고속 캐시
> - TLB 히트: 가상 주소가 TLB에 존재하여 빠르게 물리 주소로 변환되는 경우
> - TLB 미스: 가상 주소가 TLB에 존재하지 않아 페이지 테이블을 참조하여 물리 주소로 변환해야 하는 경우
> - TLB 미스가 발생하면 페이지 테이블을 참조하여 물리 주소로 변환해야 하므로, 처리 속도가 느려진다. 따라서 TLB의 효율성을 높이는 것이 중요하다.

#### 스와핑
- 가상 메모리 시스템에서, 메모리가 부족할 때 프로세스의 일부 또는 전체를 보조 기억 장치로 이동시키는 과정
- 스와핑이 발생하면, 프로세스의 실행이 일시 중단되고 필요한 데이터가 보조 기억 장치에서 메인 메모리로 로드될 때까지 기다려야 한다. 
- 따라서 스와핑이 자주 발생하면 시스템 성능이 저하될 수 있다. 
- 운영체제는 스와핑을 최소화하기 위해 메모리 관리 알고리즘을 사용하여 어떤 프로세스를 스와핑할지 결정한다. (예: LRU, FIFO, LFU 등)

#### 페이지 폴트
- 가상 메모리 시스템에서, 프로세스가 접근하려는 페이지가 메인 메모리에 존재하지 않을 때 발생하는 예외 상황
- 페이지 폴트가 발생하면, 운영체제는 해당 페이지를 보조 기억 장치에서 메인 메모리로 로드하여 프로세스가 계속 실행할 수 있도록 한다.
- 페이지 폴트가 자주 발생하면 시스템 성능이 저하될 수 있다. 
- 운영체제는 페이지 폴트를 최소화하기 위해 메모리 관리 알고리즘을 사용하여 어떤 페이지를 메인 메모리에 유지할지 결정한다.

#### 페이지 폴트와 스와핑 과정
 1. 프로세스가 가상 주소에 접근하려고 할 때, 해당 페이지가 메인 메모리에 존재하지 않으면 페이지 폴트가 발생한다.
 2. 운영체제는 페이지 폴트를 처리하기 위해, 필요한 페이지를 보조 기억 장치에서 메인 메모리로 로드한다.
 3. 메인 메모리에 공간이 부족한 경우, 운영체제는 스와핑을 통해 다른 프로세스의 일부 또는 전체를 보조 기억 장치로 이동시켜 메인 메모리에 공간을 확보한다.
 4. 필요한 페이지가 메인 메모리에 로드된 후, 프로세스는 페이지 폴트가 발생한 가상 주소에 접근하여 계속 실행할 수 있다.
 

페이지 폴트와 스와핑이 자주 발생하면 시스템 성능이 저하될 수 있으므로, <br>
운영체제는 메모리 관리 알고리즘을 사용하여 어떤 페이지를 메인 메모리에 유지할지 결정한다.


> #### 페이지와 프레임
> - 페이지(Page): 가상 메모리를 고정 크기의 블록으로 나눈 단위
> - 프레임(Frame): 메인 메모리를 고정 크기의 블록으로 나눈 단위
> - 페이지와 프레임의 크기는 동일하며, 페이지는 가상 주소 공간에서, 프레임은 물리 주소 공간에서 사용된다.
> - 페이지 테이블(Page Table): 가상 주소를 물리 주소로 변환하는 데 사용되는 데이터 구조로, 각 페이지가 어떤 프레임에 매핑되어 있는지를 저장한다.

### 스레싱
- 시스템에서 프로세스가 너무 많은 페이지 폴트를 발생시켜 CPU가 페이지 폴트 처리에 대부분의 시간을 소비하는 현상
- 스레싱이 발생하면 시스템 성능이 급격히 저하되며, 프로세스가 정상적으로 실행되지 못할 수 있다. 
- 운영체제는 스레싱을 방지하기 위해 메모리 관리 알고리즘을 사용하여 어떤 페이지를 메인 메모리에 유지할지 결정한다.
- 스레싱이 발생하는 경우, 시스템은 페이지 폴트 처리에 대부분의 시간을 소비하게 되어 실제로 프로세스가 실행되는 시간이 매우 짧아진다.

#### 작업 세트
- 작업 세트(Working Set): 프로세스가 일정 시간 동안 참조하는 페이지들의 집합
- 작업 세트 크기: 프로세스가 참조하는 페이지의 수

#### PFF(Page Fault Frequency)
- 페이지 폴트 빈도(Page Fault Frequency): 프로세스가 일정 시간 동안 발생시키는 페이지 폴트의 빈도
- PFF가 높으면 스레싱이 발생할 가능성이 높아진다. 
- 운영체제는 PFF를 모니터링하여 스레싱이 발생할 가능성이 높아지는 경우, 프로세스의 작업 세트를 메인 메모리에 유지하도록 조정하여 스레싱을 방지할 수 있다.

### 메모리 할당
- 프로세스가 실행되기 위해 필요한 메모리를 운영체제가 할당하는 과정
#### 연속 할당(Contiguous Allocation)
  - 프로세스에 필요한 메모리를 연속된 블록으로 할당하는 방식
  - 고정 분할 방식
    - 메모리를 고정 크기의 블록으로 나누어 관리하는 방식으로, 각 프로세스는 하나의 블록에 할당된다.
    - 내부 단편화의 문제가 발생할 수 있다.
  - 가변 분할 방식
    - 메모리를 가변 크기의 블록으로 나누어 관리하는 방식으로, 각 프로세스는 필요한 크기의 블록에 할당된다.
    - 내부 단편화는 발생하지 않으며, 외부 단편화의 문제가 발생할 수 있다.
    - 메모리 할당 알고리즘(예: First Fit, Best Fit, Worst Fit)을 사용하여 어떤 블록을 프로세스에 할당할지 결정한다.
    - First Fit: 가장 먼저 발견되는 충분히 큰 블록에 할당하는 방식
    - Best Fit: 가장 작은 충분히 큰 블록에 할당하는 방식
    - Worst Fit: 가장 큰 블록에 할당하는 방식
#### 비연속 할당(Non-contiguous Allocation)
  - 프로세스에 필요한 메모리를 연속되지 않은 블록으로 할당하는 방식 (예: 페이징, 세그멘테이션, 페이지드 세그멘테이션)
  - 페이지 테이블이나 세그먼트 테이블을 사용하여 프로세스의 가상 주소를 물리 주소로 변환한다.
  - 내부 단편화는 발생하지 않으며, 외부 단편화의 문제가 발생할 수 있다.
  1. 페이징(Paging)  
    - 메모리를 고정 크기의 페이지로 나누어 관리하는 방식으로, 프로세스의 가상 주소를 페이지 단위로 물리 주소로 변환한다.
    - 페이지 테이블을 사용하여 페이지 번호와 프레임 번호를 매핑한다.
  2. 세그멘테이션(Segmentation)  
     - 메모리를 가변 크기의 세그먼트로 나누어 관리하는 방식으로, 프로세스의 가상 주소를 세그먼트 단위로 물리 주소로 변환한다.
     - 세그먼트 테이블을 사용하여 세그먼트 번호와 물리 주소를 매핑한다.
  3. 페이지드 세그멘테이션(Paged Segmentation)
  - 세그멘테이션과 페이징을 결합한 방식으로, 메모리를 가변 크기의 세그먼트로 나누고, 각 세그먼트를 고정 크기의 페이지로 나누어 관리한다.
  - 세그먼트 테이블과 페이지 테이블을 사용하여 세그먼트 번호와 페이지 번호를 매핑한다. 

**내부 단편화(Internal Fragmentation)**<br>
연속 할당 방식에서, 프로세스에 할당된 메모리 블록이 프로세스가 실제로 사용하는 메모리보다 클 때 발생하는 낭비된 메모리 공간 <br>
**외부 단편화(External Fragmentation)**<br>
비연속 할당 방식에서, 메모리 블록이 여러 개의 작은 조각으로 나뉘어져 있어, 프로세스가 필요한 크기의 메모리를 할당받지 못하는 현상


### 페이지 교체 알고리즘
- 페이지 폴트가 발생했을 때, 어떤 페이지를 메인 메모리에서 제거할지 결정하는 알고리즘
#### 오프라인 알고리즘
- 미래의 페이지 참조 패턴을 알고 있다고 가정하는 알고리즘으로,
- 최적 페이지 교체 알고리즘(Optimal Page Replacement Algorithm)
  - 페이지 폴트가 발생했을 때, 앞으로 가장 오랫동안 참조되지 않을 페이지를 제거하는 방식
  - 가장 이상적인 알고리즘이지만, 실제로 구현하기 어렵다.
#### 온라인 알고리즘
- 미래의 페이지 참조 패턴을 알 수 없다고 가정하는 알고리즘으로,
- FIFO(First-In, First-Out)
  - 가장 먼저 메인 메모리에 들어온 페이지를 제거하는 방식
- LRU(Least Recently Used)
  - 가장 오랫동안 참조되지 않은 페이지를 제거하는 방식
- LFU(Least Frequently Used)
  - 가장 적게 참조된 페이지를 제거하는 방식
- NUR(Not Used Recently) 
  - Clock 알고리즘이라고도 불리는 방식으로, 페이지에 참조 비트를 사용하여 페이지를 선택하는 방식
  - 최근에 참조되지 않은 페이지를 제거하는 방식으로, LRU와 유사하지만 참조 비트만 사용하여 페이지를 선택한다.
  - 페이지에 시계 핸들을 사용하여 참조 비트를 관리하는 방식으로, 페이지 폴트가 발생했을 때 시계 핸들을 돌면서 참조 비트가 0인 페이지를 제거하는 방식 

#### LRU의 구현 방식(해시 테이블과 연결 리스트)
LRU 알고리즘을 구현하기 위해 해시 테이블과 연결 리스트를 사용할 수 있다. <br>
- 해시 테이블: 페이지 번호를 키로 사용하여 페이지의 위치를 빠르게 찾을 수 있도록 한다.
- 연결 리스트: 페이지의 참조 순서를 유지하기 위해 사용한다. <br> 가장 최근에 참조된 페이지가 리스트의 앞에 위치하고, 가장 오랫동안 참조되지 않은 페이지가 리스트의 뒤에 위치하도록 관리한다.
LRU 알고리즘의 구현 과정은 다음과 같다.
1. 페이지가 참조될 때, 해시 테이블을 사용하여 해당 페이지가 메인 메모리에 존재하는지 확인한다.
2. 페이지가 메인 메모리에 존재하는 경우, 연결 리스트에서 해당 페이지를 찾아 가장 최근에 참조된 페이지로 이동시킨다.
3. 페이지가 메인 메모리에 존재하지 않는 경우, 페이지 폴트가 발생한다. 이 때, 메인 메모리에 공간이 부족한 경우, 연결 리스트의 가장 뒤에 위치한 페이지(가장 오랫동안 참조되지 않은 페이지)를 제거한다.
4. 새로운 페이지를 메인 메모리에 로드하고, 해시 테이블에 페이지 번호와 페이지의 위치를 저장한다. 또한, 연결 리스트의 앞에 새로운 페이지를 추가하여 가장 최근에 참조된 페이지로 관리한다.
5. 페이지가 참조될 때마다 이 과정을 반복하여 LRU 알고리즘을 구현한다.
