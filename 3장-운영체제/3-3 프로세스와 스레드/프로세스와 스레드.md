# 3. 프로세스와 스레드
##### 프로세스
- 실행 중인 프로그램으로, 운영체제에서 자원을 할당받아 실행되는 단위
- 독립된 메모리 공간과 시스템 자원을 갖는다
- 프로세스 간에는 메모리 공간이 격리되어 있어 서로의 데이터를 직접 접근할 수 없다
- 운영체제에서 관리되며, 프로세스 간 통신(IPC)을 통해 데이터를 교환할 수 있다
- 생성, 실행, 대기, 종료 등의 상태를 가지며, 운영체제는 프로세스 스케줄링을 통해 CPU 시간을 할당한다.
### 스레드
- 프로세스 내에서 실행되는 작은 단위로, 프로세스의 실행 흐름을 구성하는 요소
- 프로세스의 메모리 공간과 시스템 자원을 공유한다
- 프로세스 내에서 독립적으로 실행되며, 프로세스 내에서 여러 스레드가 동시에 실행될 수 있다
- 프로세스보다 가볍고 생성과 종료가 빠르며, 스레드 간에는 메모리 공간이 공유되므로 데이터 교환이 용이하다
- 프로세스 내에서 병렬 처리를 가능하게 하며, 멀티스레딩을 통해 프로그램의 성능을 향상시킬 수 있다.

## 3.1 프로세스와 컴파일 과정
### 1) 전처리
- 소스 코드에서 주석 제거, 매크로 확장, 헤더 파일 포함 등의 작업을 수행하는 단계
- 전처리된 코드는 컴파일러가 이해할 수 있는 형태로 변환
### 2) 컴파일
- 전처리된 코드를 어셈블리어로 변환하는 단계
- 컴파일러는 소스 코드를 분석하여 최적화된 어셈블리어 코드를 생성
### 3) 어셈블리
- 어셈블리어 코드를 기계어로 변환하는 단계
- 어셈블러는 어셈블리어 명령을 해당하는 기계어 명령으로 변환하여 오브젝트 파일을 생성
### 4) 링킹
- 여러 오브젝트 파일과 라이브러리를 결합하여 실행 가능한 프로그램을 생성하는 단계
- 링커는 외부 참조를 해결하고, 필요한 라이브러리를 포함하여 최종 실행 파일을 생성
### 5) 로딩
- 실행 파일을 메모리에 적재하여 프로그램이 실행될 수 있도록 하는 단계
- 로더는 실행 파일을 메모리에 적재하고, 필요한 라이브러리를 로드하여 프로그램이 실행될 준비를 한다.

> #### 정적 라이브러리와 동적 라이브러리
> - 정적 라이브러리
>   - 컴파일 시 프로그램에 포함되어 실행 파일에 통합되는 라이브러리
>   - 장점: 실행 파일이 독립적으로 실행될 수 있으며, 라이브러리 버전 관리가 필요 없다.
>   - 단점: 실행 파일의 크기가 커지고, 라이브러리를 업데이트하려면 전체 프로그램을 다시 컴파일해야 한다.
> - 동적 라이브러리
>   - 프로그램 실행 시 필요할 때 로드되어 사용하는 라이브러리
>   - 장점: 실행 파일의 크기가 작아지고, 라이브러리를 업데이트할 때 전체 프로그램을 다시 컴파일할 필요가 없다.
>   - 단점: 실행 파일이 라이브러리에 의존하게 되어, 라이브러리가 없거나 버전이 맞지 않으면 프로그램이 실행되지 않을 수 있다.

## 3.2 프로세스의 상태
### 1) 생성 (New)
- 프로세스가 생성되어 운영체제에 등록된 상태
- 프로세스 제어 블록(PCB)이 할당되고, 초기화된다
### 2) 준비 (Ready)
- CPU 할당을 기다리는 상태
- 프로세스가 실행될 준비가 되었지만, 아직 CPU를 할당받지 않은 상태
### 3) 실행 (Running)
- CPU를 할당받아 명령을 실행하는 상태
- 프로세스가 실제로 CPU에서 실행되고 있는 상태
### 4) 대기 (Waiting)
- 특정 이벤트(예: I/O 완료, 자원 확보 등)를 기다리는 상태
- 프로세스가 CPU를 할당받았지만, 필요한 자원이 준비되지 않아 실행을 일시 중단한 상태
### 5) 종료 (Terminated)
- 프로세스가 실행을 마치고 종료된 상태
- 프로세스가 종료되면 운영체제는 PCB를 해제하고, 자원을 반환한다.

## 3.3 프로세스의 메모리 구조
- 스택: 함수 호출과 지역 변수 저장에 사용되는 메모리 영역 (동적 영역)
- 힙: 동적 메모리 할당에 사용되는 메모리 영역 (동적 영역)
- 데이터 세그먼트: 전역 변수와 정적 변수가 저장되는 메모리 영역 (정적 영역)
- 코드 세그먼트: 프로그램의 실행 코드가 저장되는 메모리 영역 (정적 영역)

### 스택
  - 함수 호출과 지역 변수 저장에 사용되는 메모리 영역
  - LIFO(Last In, First Out) 구조로 관리되며, 함수가 호출될 때마다 새로운 스택 프레임이 생성되고, 함수가 종료되면 해당 프레임이 제거된다.
  - 스택은 자동으로 관리되며, 메모리 할당과 해제가 빠르지만, 크기가 제한적이다.
  - 스택 오버플로우(Stack Overflow)는 스택이 할당된 메모리 공간을 초과하여 사용할 때 발생하는 오류로, 프로그램이 비정상적으로 종료될 수 있다.
### 힙
  - 동적 메모리 할당에 사용되는 메모리 영역
  - 메모리 할당과 해제가 프로그래머에 의해 명시적으로 관리되며, 크기가 유동적이다.
  - 힙은 스택보다 크기가 크고, 동적으로 할당할 수 있지만, 메모리 단편화와 관리의 어려움이 있을 수 있다.
  - 메모리 누수(Memory Leak)는 힙에 할당된 메모리가 해제되지 않고 계속해서 사용되는 현상으로, 
  - 시스템 자원을 낭비하고, 프로그램의 성능 저하나 시스템의 불안정을 초래할 수 있다.


### 데이터 세그먼트(feat. BSS 세그먼트)
- 전역 변수와 정적 변수가 저장되는 메모리 영역
- 초기화된 전역 변수는 데이터 세그먼트의 초기화된 부분에 저장되고, 초기화되지 않은 전역 변수는 BSS 세그먼트에 저장된다.
- 데이터 세그먼트는 프로그램이 시작될 때 할당되고, 프로그램이 종료될 때 해제된다.
> #### BSS 세그먼트
> - 초기화되지 않은 전역 변수와 정적 변수가 저장되는 메모리 영역
> - BSS는 "Block Started by Symbol"의 약자로, 초기화되지 않은 데이터를 저장하는 영역을 의미한다.
> - BSS 세그먼트는 프로그램이 시작될 때 운영체제에 의해 자동으로 0으로 초기화되며, 프로그램이 종료될 때 해제된다.

### 코드 세그먼트(feat. Data 세그먼트)
- 프로그램의 실행 코드가 저장되는 메모리 영역
- 코드 세그먼트는 읽기 전용으로, 프로그램이 실행될 때 할당되고, 프로그램이 종료될 때 해제된다.

> #### 코드 세그먼트
> - 프로그램의 실행 코드가 저장되는 메모리 영역
> - 읽기 전용으로, 프로그램이 실행될 때 할당되고, 프로그램이 종료될 때 해제된다.
> - 프로그램의 명령어가 저장되는 영역으로, CPU가 명령어를 실행할 때 참조된다.

## 3.4 PCB (Process Control Block)
- 프로세스의 상태와 정보를 저장하는 데이터 구조
- 일반 사용자가 접근하지 못하도록 커널 스택의 상단에 위치한다.
- PCB에는 프로세스 ID, 프로세스 상태, 프로그램 카운터, 레지스터 상태, 메모리 관리 정보, 입출력 상태 정보 등이 포함된다.
- 운영체제는 PCB를 사용하여 프로세스를 관리하고, 스케줄링과 문제 해결을 수행한다.
- PCB는 프로세스의 실행 상태를 저장하는 중요한 데이터 구조로, 운영체제가 프로세스 간의 전환과 관리를 효율적으로 수행할 수 있도록 지원한다.

> ### 메타데이터
> - 데이터에 대한 정보를 담고 있는 데이터로, PCB는 프로세스의 메타데이터를 포함한다.
> - PCB의 메타데이터에는 프로세스 ID, 프로세스 상태, 프로그램 카운터, 레지스터 상태, 메모리 관리 정보, 입출력 상태 정보 등이 포함된다.
> - 프로세스의 실행 상태와 관련된 정보를 제공하여 운영체제가 프로세스를 효율적으로 관리할 수 있도록 지원한다.


### PCB의 구조
- 프로세스 ID (PID): 프로세스를 고유하게 식별하는 번호
- 프로세스 스케줄링 상태: 프로세스의 현재 상태 (예: 준비, 실행, 대기, 종료)
- 프로그램 카운터: 다음에 실행할 명령어의 주소
- 레지스터 상태: 프로세스가 사용하는 CPU 레지스터의 현재 값
- 메모리 관리 정보: 프로세스가 사용하는 메모리 영역과 관련된 정보
- 입출력 상태 정보: 프로세스가 사용하는 입출력 장치와 관련된 정보
- CPU 스케줄링 정보: 프로세스의 우선순위와 스케줄링 관련 정보
- 프로세스 권한 정보: 프로세스가 접근할 수 있는 자원과 권한에 대한 정보
- 계정 정보: 프로세스를 생성한 사용자와 관련된 정보

### 컨텍스트 스위칭
- PCB를 사용하여 프로세스 간의 전환을 관리하는 과정
- 운영체제가 CPU를 한 프로세스에서 다른 프로세스로 전환하는 과정
- 컨텍스트 스위칭이 발생하면, 운영체제는 현재 실행 중인 프로세스의 PCB에 현재 상태를 저장하고, 다음에 실행할 프로세스의 PCB에서 상태를 불러와 CPU에 할당한다.
- 프로세스 간의 전환을 가능하게 하지만, CPU 시간을 소비하는 작업이므로 빈번하게 발생하면 시스템 성능이 저하될 수 있다.
- 운영체제는 컨텍스트 스위칭을 최소화하기 위해 효율적인 스케줄링 알고리즘을 사용하여 프로세스 간의 전환을 관리한다.

#### 컨텍스트 스위칭의 비용
- CPU 시간 소비: 컨텍스트 스위칭은 현재 실행 중인 프로세스의 상태를 PCB에 저장하고, 다음 프로세스의 상태를 불러오는 작업이 필요하므로 CPU 시간을 소비한다.
- 캐시 무효화: 컨텍스트 스위칭이 발생하면, CPU 캐시가 무효화되어 다음 프로세스가 필요한 데이터를 다시 로드해야 하므로, 시스템 성능이 저하될 수 있다.
- 메모리 관리: 컨텍스트 스위칭이 발생하면, 운영체제가 메모리 관리 정보를 업데이트해야 하므로, 추가적인 작업이 필요하다.
- 스레드: 컨텍스트 스위칭은 프로세스 간뿐만 아니라, 스레드 간에도 발생할 수 있다.
  - 스레드 간의 전환도 CPU 시간을 소비하는 작업이므로, 빈번하게 발생하면 시스템 성능이 저하될 수 있다.


## 3.5 멀티프로세싱
- 여러 프로세스가 동시에 실행되는 환경
- 멀티프로세싱 시스템에서는 여러 프로세스가 CPU 자원을 공유하며, 운영체제가 프로세스 간의 스케줄링을 통해 CPU 시간을 할당한다.
- 시스템의 성능을 향상시키고, 여러 작업을 동시에 처리할 수 있도록 지원한다.
- 멀티프로세싱 시스템에서는 프로세스 간의 통신과 동기화가 중요하며, 운영체제는 이를 지원하기 위한 다양한 메커니즘을 제공한다.

### 브라우저와 멀티 프로세스 구조
#### 1) 브라우저 프로세스
- 브라우저의 핵심 기능을 담당하는 프로세스
- 사용자 인터페이스(UI) 관리, 탭 관리, 네트워크 통신, 보안 관리 등 브라우저의 전반적인 기능을 수행한다.
#### 2) 렌더러 프로세스
- 웹 페이지의 렌더링과 관련된 작업을 담당하는 프로세스
- HTML, CSS, JavaScript 등의 웹 콘텐츠를 해석하고, 웹 페이지를 화면에 표시하는 역할을 한다.
- 각 탭마다 별도의 렌더러 프로세스가 할당되어, 하나의 탭에서 발생한 문제가 다른 탭에 영향을 미치지 않도록 한다.
#### 3) GPU 프로세스
- 그래픽 처리와 관련된 작업을 담당하는 프로세스
- 웹 페이지의 그래픽 요소를 처리하고, GPU를 활용하여 렌더링 성능을 향상시키는 역할을 한다.
- GPU 프로세스는 렌더러 프로세스와 협력하여 웹 페이지의 그래픽 요소를 효율적으로 처리한다.
#### 4) 플러그인 프로세스
- 브라우저에서 사용하는 플러그인과 관련된 작업을 담당하는 프로세스
- 플래시, PDF 뷰어 등과 같은 플러그인을 실행하는 역할을 한다.
- 플러그인 프로세스는 브라우저 프로세스와 통신하여 플러그인의 기능을 제공하며, 플러그인에서 발생한 문제가 브라우저 전체에 영향을 미치지 않도록 격리한다.

### IPC (Inter-Process Communication)
- 프로세스 간의 통신을 가능하게 하는 메커니즘
- 멀티프로세싱 환경에서 프로세스 간의 데이터 교환과 동기화를 지원한다.
- IPC 메커니즘에는 파이프, 메시지 큐, 공유 메모리, 소켓 등이 있다.
- IPC를 통해 프로세스는 서로 데이터를 교환하고, 협력하여 작업을 수행할 수 있다.


#### 공유 메모리
- 여러 프로세스가 동시에 접근할 수 있는 메모리 영역을 공유하여 데이터를 교환하는 방식
- 빠른 데이터 교환이 가능하지만, 동기화 문제가 발생할 수 있다.

#### 파일
- 프로세스 간에 파일을 통해 데이터를 교환하는 방식
- 파일을 사용하여 데이터를 저장하고, 다른 프로세스가 해당 파일을 읽어서 데이터를 교환할 수 있다.

#### 메시지 큐
- 프로세스 간에 메시지를 전달하는 방식으로, 메시지 큐를 통해 데이터를 교환한다.
- 메시지 큐는 동기화 문제를 해결할 수 있지만, 데이터 교환 속도가 공유 메모리에 비해 느릴 수 있다.

#### 소켓
- 네트워크 통신을 통해 프로세스 간의 데이터를 교환하는 방식
- 소켓을 사용하여 프로세스는 서로 다른 컴퓨터에 있는 프로세스와도 통신할 수 있다.

#### 익명 파이프
- 부모 프로세스와 자식 프로세스 간의 통신을 위해 사용되는 파이프
- 단방향 통신을 지원하며, 부모 프로세스가 자식 프로세스에게 데이터를 보내거나, 자식 프로세스가 부모 프로세스에게 데이터를 보낼 수 있다.
- 프로세스 간의 통신을 간단하게 구현할 수 있지만, 부모 프로세스와 자식 프로세스 간에만 사용할 수 있다.

#### 명명된 파이프
- 프로세스 간의 통신을 위해 사용되는 파이프 중 하나로, 이름이 지정된 파이프
- 양방향 통신을 지원하며, 여러 프로세스가 동일한 이름의 파이프에 접근하여 데이터를 교환할 수 있다.

## 3.6 스레드와 멀티스레딩
- 스레드는 프로세스 내에서 실행되는 작은 단위로, 프로세스의 실행 흐름을 구성하는 요소
- 멀티스레딩은 하나의 프로세스 내에서 여러 스레드가 동시에 실행되는 환경을 의미한다.
- 멀티스레딩을 통해 프로그램의 성능을 향상시키고, 병렬 처리를 가능하게 한다.
- 스레드는 프로세스의 메모리 공간과 시스템 자원을 공유하므로, 스레드 간의 데이터 교환이 용이하지만, 동기화 문제가 발생할 수 있다.


### 스레드
- 프로세스 내에서 실행되는 작은 단위로, 프로세스의 실행 흐름을 구성하는 요소
- 프로세스의 메모리 공간과 시스템 자원을 공유한다
- 프로세스 내에서 독립적으로 실행되며, 프로세스 내에서 여러 스레드가 동시에 실행될 수 있다
- 프로세스보다 가볍고 생성과 종료가 빠르며, 스레드 간에는 메모리 공간이 공유되므로 데이터 교환이 용이하다
- 프로세스 내에서 병렬 처리를 가능하게 하며, 멀티스레딩을 통해 프로그램의 성능을 향상시킬 수 있다.

### 멀티스레딩
- 하나의 프로세스 내에서 여러 스레드가 동시에 실행되는 환경을 의미한다.
- 멀티스레딩을 통해 프로그램의 성능을 향상시키고, 병렬 처리를 가능하게 한다.
- 스레드는 프로세스의 메모리 공간과 시스템 자원을 공유하므로, 스레드 간의 데이터 교환이 용이하지만, 동기화 문제가 발생할 수 있다.
- 멀티스레딩을 구현할 때는 스레드 간의 동기화와 자원 관리를 신중하게 고려해야 하며, 운영체제는 이를 지원하기 위한 다양한 메커니즘을 제공한다

> #### 동시성
> - 여러 스레드가 동시에 실행되는 환경에서 스레드 간의 작업이 겹치거나 교차하는 현상
> - 멀티스레딩 환경에서 발생할 수 있으며 스레드 간의 동기화와 자원 관리를 신중하게 고려해야 한다.

## 3.7 공유 자원과 임계 영역
### 공유 자원
- 여러 프로세스가 동시에 접근할 수 있는 자원으로, 메모리, 파일, 입출력 장치 등이 포함된다.
- 공유 자원에 대한 동시 접근은 데이터 일관성 문제와 경쟁 조건을 초래할 수 있다.
- 운영체제는 공유 자원에 대한 접근을 제어하기 위해 동기화 메커니즘을 제공한다.

### 임계 영역
- 공유 자원에 접근하는 코드의 부분으로, 동시에 하나의 프로세스만 접근할 수 있도록 해야 하는 영역
- 임계 영역에 대한 동시 접근을 방지하기 위해 운영체제는 상호 배제(Mutual Exclusion) 과정을 제공한다.
- 상호 배제는 프로세스가 임계 영역에 진입하기 전에 다른 프로세스가 이미 진입해 있는지 확인하고, 진입이 허용되지 않으면 대기하도록 하는 방식으로 구현된다.
- 임계 영역 문제는 데이터 일관성 문제와 경쟁 조건을 초래할 수 있으므로, 운영체제는 효율적인 동기화 메커니즘을 사용하여 이를 해결한다.

#### 뮤텍스와 세마포어
- 뮤텍스(Mutex): 상호 배제를 구현하는 동기화 객체로, 하나의 프로세스만 소유할 수 있다. 
  - 프로세스가 뮤텍스를 소유하면 다른 프로세스는 해당 뮤텍스에 접근할 수 없으며, 대기해야 한다.
- 세마포어(Semaphore): 뮤텍스와 유사하지만, 여러 프로세스가 동시에 접근할 수 있도록 허용하는 동기화 객체
  - 카운터를 사용하여 접근 가능한 프로세스의 수를 제어한다.


> 세마포어의 종류
> - 이진 세마포어(Binary Semaphore)
>   - 카운터가 0 또는 1인 세마포어로, 뮤텍스와 유사하게 상호 배제를 구현하는 데 사용된다.
>   - 하나의 프로세스만 접근할 수 있도록 허용하며, 다른 프로세스는 대기해야 한다.
>   - 뮤텍스와 달리, 이진 세마포어는 소유 개념이 없으며, 프로세스가 세마포어를 소유하지 않아도 접근할 수 있다.
> - 카운팅 세마포어(Counting Semaphore)
>   - 카운터가 0 이상의 값을 가질 수 있는 세마포어로, 여러 프로세스가 동시에 접근할 수 있도록 허용하는 데 사용된다.
>   - 카운터는 접근 가능한 프로세스의 수를 나타내며, 프로세스스가 세마포어에 접근할 때마다 카운터가 감소하고, 접근이 끝나면 카운터가 증가한다.
>   - 카운팅 세마포어는 리소스 풀(Resource Pool)과 같은 상황에서 유용하게 사용된다. 예를 들어, 데이터베이스 연결 풀에서 동시에 사용할 수 있는 연결의 수를 제한하는 데 사용할 수 있다.


#### 모니터
- 둘 이상의 스레드나 프로세스가 공유 자원에 접근할 때, 상호 배제를 보장하는 메커니즘

## 3.8 교착 상태(Deadlock)
- 둘 이상의 프로세스가 서로의 자원을 기다리며 무한히 대기하는 상태
### 교착 상태의 원인
#### 1) 상호 배제(Mutual Exclusion)
- 자원이 한 번에 하나의 프로세스만 사용할 수 있는 경우, 상호 배제가 발생한다. 
- 예: 프린터와 같은 입출력 장치는 한 번에 하나의 프로세스만 사용할 수 있다.
#### 2) 점유와 대기(Hold and Wait)
- 프로세스가 이미 자원을 점유하고 있으면서, 다른 자원을 기다리는 경우, 점유와 대기가 발생한다.
- 예: 프로세스 A가 프린터를 점유하고 있으면서, 다른 자원인 파일을 기다리는 경우
#### 3) 비선점(Non-preemption)
- 이미 할당된 자원을 강제로 빼앗을 수 없는 경우, 비선점이 발생한다.
- 예: 프로세스 A가 프린터를 점유하고 있을 때, 운영체제가 강제로 프린터를 빼앗아 다른 프로세스에게 할당할 수 없는 경우
- #### 4) 순환 대기(Circular Wait) (= 환형 대기)
- 프로세스들이 서로 순환적으로 자원을 기다리는 경우, 순환 대기가 발생한다.
- 예: 프로세스 A가 프로세스 B가 점유한 자원을 기다리고, 프로세스 B가 프로세스 C가 점유한 자원을 기다리고, 프로세스 C가 프로세스 A가 점유한 자원을 기다리는 경우

### 교착 상태의 해결 방법
#### 1) 예방(Prevention)
- 교착 상태의 원인 중 하나 이상을 제거하여 교착 상태가 발생하지 않도록 하는 방법
- 예: 상호 배제를 제거하여 자원을 동시에 사용할 수 있도록 허용하거나, 점유와 대기를 제거하여 프로세스가 자원을 점유하기 전에 모든 필요한 자원을 요청하도록 하는 방법
#### 2) 회피(Avoidance)
- 프로세스가 자원을 요청할 때, 교착 상태가 발생할 가능성이 있는지 판단하여 요청을 허용하거나 거부하는 방법
- 예: 은행원 알고리즘(Banker's Algorithm)을 사용하여 프로세스의 자원 요청이 안전한 상태를 유지하는지 판단하는 방법
> #### 은행원 알고리즘(Banker's Algorithm)
> - 교착 상태 회피 알고리즘으로, 프로세스의 자원 요청이 안전한 상태를 유지하는지 판단하여 요청을 허용하거나 거부하는 방법
> - 프로세스가 자원을 요청할 때, 은행원 알고리즘은 현재 시스템의 자원 상태와 프로세스의 최대 요구량을 고려하여 요청이 안전한 상태를 유지하는지 판단한다.
> - 안전한 상태란, 시스템이 모든 프로세스의 최대 요구량을 충족시킬 수 있는 상태를 의미한다. 
> - 만약 요청이 안전한 상태를 유지한다면, 요청을 허용하고 자원을 할당한다. 그렇지 않으면, 요청을 거부하여 교착 상태가 발생하지 않도록 한다.
#### 3) 탐지(Detection)
- 시스템에서 교착 상태가 발생했는지 주기적으로 검사하여 탐지하는 방법
- 예: 자원 할당 그래프(Resource Allocation Graph)를 사용하여 교착 상태를 탐지하는 방법
#### 4) 회복(Recovery)
- 교착 상태가 탐지된 후, 시스템이 교착 상태에서 벗어나도록 조치를 취하는 방법
- 예: 프로세스 중 하나를 강제로 종료하거나, 프로세스가 점유한 자원을 강제로 빼앗아 다른 프로세스에게 할당하는 방법
